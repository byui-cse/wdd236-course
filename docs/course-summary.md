# WDD 236 Course Summary

## Course Overview

WDD 236: Frontend Architecture & Engineering is the bridge between web mechanics and professional frontend product engineering.

Students enter this course after learning foundational mechanics in WDD 235 (HTML, CSS, JavaScript, basic DOM work, and deployment). WDD 236 builds on those fundamentals by emphasizing architecture, maintainability, testing discipline, accessibility, and technical communication.

The course centers on a progressive arc:

1. Think like an architect.
2. Build like an engineer.
3. Validate like a quality team.
4. Deliver like a professional.

Students move from planning user experiences and information systems to implementing encapsulated components, automating quality checks, and shipping a polished frontend product.

## Instructional Approach

The course uses a mentor-style model where the instructor coaches teams through applied work. Learning is organized around the BYU-Idaho learning model architecture used in this course:

- **Prepare:** Students come to team meetings with research and progress from assigned work.
- **Teach One Another:** Teams are expected to learn collaboratively and rely on each member's strengths.
- **Ponder/Prove:** Students reflect on what they are learning and validate understanding through experimentation and implementation.

A central expectation is that students move beyond passive reading by building, testing, comparing, and documenting their decisions.

## Course Arc and Sequence

WDD 236 follows a 13-week progression that intentionally shifts emphasis from design planning to implementation rigor and final delivery:

- **Weeks 1-2: Design and Architecture Foundations**
  Students learn to translate user and stakeholder needs into technical blueprints using information architecture, wireframes, and system-level thinking.
- **Weeks 3-4: Native Component Engineering**
  Students build reusable UI elements with browser-native component APIs (Custom Elements, Shadow DOM) and component-driven design practices.
- **Weeks 5-6: Testing and Reliability**
  Students establish quality gates with automated unit and integration testing, including robust boundary and state-driven test scenarios.
- **Weeks 7-8: Advanced JavaScript and Modular Architecture**
  Students deepen engineering fluency with asynchronous flow, modular patterns, state management, and code quality evaluation.
- **Weeks 9-10: Accessibility and Discoverability**
  Students implement accessibility-first interaction patterns and technical SEO/AEO improvements, including semantic metadata and structured data.
- **Weeks 11-13: Capstone Delivery**
  Students execute a three-phase capstone: strategic architecture, build-and-test execution, and production polish (A11y verification, SEO finalization, deployment).

This sequence helps students internalize that architecture is not separate from coding: architecture directs code quality, testing, accessibility, and long-term maintainability.

## Learning Outcomes

By the end of WDD 236, students should be able to:

1. Translate user needs into technical blueprints using sitemaps, wireframes, and design system documentation.
2. Apply automated testing (unit and integration) to ensure application logic is bug-resistant.
3. Architect and implement advanced JavaScript patterns, including asynchronous flow and modular architecture.
4. Implement accessibility patterns that support professional WCAG expectations.
5. Evaluate and refine AI-generated test suites and code reviews for technical accuracy and architectural integrity.

These outcomes intentionally extend the WDD 235 prerequisite outcomes. Students do not re-learn mechanics; they operationalize them at a professional engineering level.

## Pedagogical Principles

Course design is guided by the following principles:

- **Architecture before implementation:** Students should articulate structure and intent before writing significant code.
- **Evidence over assumption:** Claims about quality should be demonstrated through tests, audits, and measurable criteria.
- **Accessibility is core engineering:** A11y is treated as a first-class quality attribute, not post-launch cleanup.
- **Encapsulation and reuse:** Component design should reduce duplication and improve maintainability.
- **Reflective engineering:** Students regularly justify decisions, discuss tradeoffs, and revise based on review feedback.
- **AI-assisted accountability:** AI can accelerate review and idea generation, but students remain responsible for correctness.

## Assessment Philosophy

Assessment is portfolio-oriented and outcome-aligned. Students compile evidence across the semester and self-assess against course outcomes, supported by completed artifacts, team work, and project deliverables.

The grading model values initiative, depth of understanding, and practical integration of concepts, not checklist completion.

Primary evidence categories include:

- Architecture artifacts (sitemaps, wireframes, technical plans)
- Component implementation quality (modularity, clarity, maintainability)
- Automated test depth and reliability
- Accessibility and SEO/AEO compliance checks
- Reflection on technical decisions and team process
- Capstone readiness and final deployment quality

## AI Use in This Course

AI is framed as a learning support tool, not a replacement for student thinking or work.

- General tutoring/research use is allowed.
- Assignment-specific limits are communicated with stoplight indicators (green/yellow/red).
- Students are expected to review, verify, and adapt AI-generated output.

In WDD 236 specifically, AI use emphasizes high-level engineering review:

- UX and architecture critique during planning
- Test case generation (especially boundary and edge scenarios)
- Code smell and maintainability audits
- Accessibility walkthrough simulation and remediation suggestions
- Final quality review against explicit standards

Students are expected to validate AI output by tracing reasoning, running tests, and confirming standards compliance.

## Tools and Workflow Expectations

Students are expected to operate in a modern web workflow with:

- VS Code (recommended)
- Node.js (LTS)
- Git and GitHub
- Team communication and coordination tools (for example, Microsoft Teams and Trello)

Course activities also stress understanding package management, build tooling, and task automation as part of professional practice.

Recommended technical stack elements for this course include:

- Browser-native component APIs
- Modern JavaScript modules and async patterns
- Automated testing frameworks (for example, Vitest)
- Accessibility and lint/audit tooling
- Structured metadata practices for technical SEO/AEO

Students should finish WDD 236 able to participate meaningfully in a modern frontend engineering workflow from planning to production delivery.

## Summary

WDD 236 develops frontend engineers, not just coders. By combining architecture practice, component engineering, automated quality strategies, accessibility standards, and responsible AI-assisted review, the course prepares students to build resilient, maintainable, and professional web applications.
