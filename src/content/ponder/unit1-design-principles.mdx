## Introduction

Before you refine your wireframes, it helps to understand the four foundational design principles that make interfaces clear and usable. **PARC** is a simple mental model used by designers to organize visual information and guide user attention.

These principles work together. When applied well, they make interfaces feel intentional and easy to navigate. When overlooked, interfaces become cluttered and confusing.

## **01** Proximity

**Proximity** means grouping related items close together and separating unrelated items.

### Why it matters

- Users naturally assume items placed together belong together
- It reduces visual clutter by creating logical zones
- It guides the eye to process information in chunks rather than individual elements

- Put related navigation options close together
- Use whitespace intentionally to separate different sections

## **02** Repetition

**Repetition** means using the same visual elements (colors, sizes, fonts, spacing, icons) consistently throughout your design.

### Why it matters

- Users learn patterns—when they see the same visual treatment, they expect the same function
- Repetition creates a coherent visual language that feels polished
- It reduces cognitive load because users don't have to re-learn how to interact

### Example: Button Consistency

<div style="border:1px solid #d1d5db;border-radius:8px;padding:16px;background:#f9fafb;margin:12px 0;">

      <div style="display:flex;flex-wrap:wrap;gap:14px;align-items:center;">

      </div>
</div>

Users have to figure out what each element does by looking at it.

<div style="border:1px solid #d1d5db;border-radius:8px;padding:16px;background:#f9fafb;margin:12px 0;">

### In Your Wireframes

- Use the same button size and spacing for similar actions
- Label similar sections with the same heading style
- Apply consistent margins between major sections
- Use repetition to reinforce your information hierarchy

## **03** Alignment

**Alignment** means arranging elements in relation to a grid or baseline so nothing feels randomly placed.

### Why it matters

- Aligned elements feel organized and professional
- Visual structure helps users predict where to find things
- It's easier to scan content when elements line up

## **04** Contrast

**Contrast** means using obvious differences to highlight important elements and create visual hierarchy.

### Why it matters

- Contrast draws attention to what matters most
- It helps users understand what is interactive vs. informational
- It aids users with visual impairments who rely on clear distinctions

### Example: Form With Errors

      <div style="max-width:360px;display:flex;flex-direction:column;gap:8px;">

                  <span style="font-size:14px;">Email</span>

            </label>
            <p style="margin:0;color:#9ca3af;font-size:12px;">Invalid email address</p>
            <label style="display:flex;flex-direction:column;gap:4px;">
                  <span style="font-size:14px;">Password</span>
                  <input disabled value="" style="height:36px;border:1px solid #9ca3af;border-radius:4px;background:white;" />

The error message is barely visible; it's not clear what's wrong.

Now the error stands out and is unmissable.

### In Your Wireframes

- Use size difference to show primary vs. secondary actions
- Use color or visual weight to differentiate sections
- Make interactive elements (buttons, links) visually distinct from static text
- Apply strong contrast for feedback (errors, success states, loading indicators)

## PARC in Action: A Real Example

Here is how PARC principles work together in a product card:

      <article style="border:1px solid #d1d5db;border-radius:8px;overflow:hidden;background:white;">

            <div style="padding:12px;display:flex;flex-direction:column;gap:8px;align-items:flex-start;">
                  <h4 style="margin:0;font-size:15px;">Product Name</h4>
                  <p style="margin:0;font-size:20px;font-weight:700;color:#b45309;">$19.99</p>
                  <p style="margin:0;font-size:13px;color:#374151;">★★★★★ (124)</p>
                  <button disabled style="width:100%;height:38px;background:#2563eb;color:white;border:0;border-radius:6px;font-weight:700;">Add to Cart</button>
                  <span style="width:100%;text-align:center;font-size:12px;color:#1d4ed8;">Save for Later</span>
            </div>
      </article>
</div>

Each principle reinforces the others:
- **Proximity** groups the image, name, and price logically
- **Repetition** uses the same spacing and font styling throughout
- **Alignment** puts everything on a clean vertical axis
- **Contrast** makes the blue "Add to Cart" button the clear focal point

## Checklist for Your Wireframes

Before you consider your wireframes done, ask yourself:

<Details summary="Proximity Checklist">
- [ ] Related form fields are grouped together
- [ ] Navigation is separated from content
- [ ] Primary actions are visually distinct from secondary actions
- [ ] I have used whitespace to separate different sections
</Details>

<Details summary="Repetition Checklist">
- [ ] All buttons of the same type look identical
- [ ] Headings use consistent sizing and weight
- [ ] Spacing is consistent between similar sections
- [ ] Icons (if any) use a consistent style
</Details>

<Details summary="Alignment Checklist" >
- [ ] Text is aligned to a baseline or grid
- [ ] Form fields and labels are aligned vertically
- [ ] Card elements line up across rows
- [ ] Nothing looks randomly placed
</Details>

<Details summary="Contrast Checklist" >
- [ ] The primary action is visually obvious
- [ ] Interactive elements stand out from static text
- [ ] Success, error, and warning states are clearly different
- [ ] Text has sufficient color contrast for readability
</Details>
