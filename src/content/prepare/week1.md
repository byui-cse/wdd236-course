> ## Tips
>
> - Look at real interfaces while you study. The goal is to see how layout, behavior, and engineering decisions connect.
> - Keep one running note that moves from interface breakdown to workflow setup so your preparation feels like one coherent system.
> - When you review tools, focus on what each tool helps you verify or improve.

## Topics to Learn

Your goal this week is to learn the following terms and ideas. You can use any learning method that works for you: articles, videos, tutorials, AI chat, or a mix.

1. Atomic interface thinking: page, region, component, and subcomponent
2. How to deconstruct a professional layout into reusable UI pieces
3. The engineering loop for this course: plan, build, test, review, and refine
4. Local development workflow basics: VS Code, Node, package scripts, and Git
5. What Vitest and ESLint are for in a frontend workflow
6. Baseline AI workflows for planning, explanation, and code review support
7. How Unit 1 connects architecture decisions to implementation work

## Submission

Treat this as evidence for Competency 1, with light setup checks for Competency 6.

Include:

- One interface decomposition artifact. Choose one format:
  - annotated screenshot
  - component inventory table
  - layout breakdown sketch
  - concept map
- For that interface, identify:
  - the major regions
  - at least five components or subcomponents
  - one component that seems most worth building first
- A short workflow note that explains:
  - the steps in your engineering loop
  - what Vitest will help you verify
  - what ESLint will help you catch
  - one appropriate use of AI during this loop
