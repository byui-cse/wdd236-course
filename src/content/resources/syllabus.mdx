## Description

WDD 236: Frontend Architecture and Engineering bridges the gap between raw coding and professional product engineering.

Students begin by mastering the architect role, where user needs are translated into technical plans through UX, UI, and Information Architecture. The technical focus then shifts to component-based engineering, where students build encapsulated, reusable UI systems using browser-native APIs and modern JavaScript module patterns.

The course emphasizes automated testing, accessibility, and long-term maintainability so students can produce resilient and standards-compliant web applications.

A key feature of this course is disciplined use of AI as a senior-level auditor rather than a shortcut. Students use AI to critique architecture, generate and refine edge-case tests, and review accessibility and code quality findings. Students remain accountable for correctness, clarity, and professional standards.

By the end of the course, students will have experience planning, building, testing, and shipping frontend products using professional engineering workflows.

## Prerequisites

**WDD 235 (Web Mechanics)**

This course assumes you have already developed foundational web skills. You should be able to:

1. Explain the semantic purpose of various HTML elements and their role in document structure.
2. Utilize CSS in a web layout.
3. Use JavaScript for basic programming and DOM manipulation.
4. Explain the interaction between a client and a server.
5. Explain the benefit of separating presentation, content, and logic.
6. Build and deploy a working application to the Internet.

If you feel rusty, review:

1. You should be very comfortable writing HTML and modern CSS. If you need a review you can read [MDN HTML Introduction](https://developer.mozilla.org/en-US/docs/Learn/Getting_started_with_the_web/HTML_basics) and [MDN CSS Introduction](https://developer.mozilla.org/en-US/docs/Learn/Getting_started_with_the_web/CSS_basics).
2. You should be comfortable with JavaScript fundamentals including variables, data types, functions, loops, and conditionals. If you need a review you can read [MDN JavaScript First Steps](https://developer.mozilla.org/en-US/docs/Learn/Getting_started_with_the_web/JavaScript_basics).
3. You should be comfortable creating websites with template-based tools using a component-based architecture.
4. Make sure you are comfortable with basic DOM manipulation with JavaScript. If you need a review you can read [MDN Manipulating Documents](https://developer.mozilla.org/en-US/docs/Learn/JavaScript/Client-side_web_APIs/Manipulating_documents).
5. Make sure you are comfortable with basic event management with JavaScript. If you need a review you can read [MDN Introduction to Events](https://developer.mozilla.org/en-US/docs/Learn/JavaScript/Building_blocks/Events).
6. You should be comfortable using Git and GitHub for collaborative workflows.

## Course Structure

### Overview

This class is designed as an engineering progression from architecture to implementation to production readiness.

In the first part of the course, you will define product direction and architecture decisions through UX/UI planning, information architecture, and component strategy. In the middle part, you will establish reliability through testing and advanced JavaScript patterns. In the final part, you will complete a capstone that demonstrates technical quality, accessibility, and deployment readiness.

The goal is to help you think and deliver like a frontend engineer: design intentionally, build modularly, test rigorously, and polish for real users.

## 13-Week Curriculum Map

| Week(s) | Theme | Key Technical Deep-Dive | AI Peer-Review and Tooling Task |
| --- | --- | --- | --- |
| 1-2 | Design and Architecture | UX/UI principles, wireframing, and information architecture | Use AI to critique a wireframe for information density and UX friction |
| 3-4 | Native Web Components | Custom Elements, Shadow DOM, encapsulated styling, and modular design | Prompt AI to help refactor a standard HTML snippet into a native web component |
| 5-6 | Testing and Reliability | Unit testing (Vitest) for logic and integration testing for UI state | Use AI to generate boundary-case tests for a custom input component |
| 7-8 | Advanced JavaScript and Modules | Closures, state management, asynchronous flow, and modular architecture | Use AI for a code-smell audit on your modular logic |
| 9-10 | Deep A11y and Technical SEO/AEO | ARIA patterns, focus management, semantic structure, and JSON-LD | Have AI simulate a screen-reader walkthrough of your custom components |
| 11 | Capstone Strategy | Phase 1: UX design, sitemap, and architecture planning | AI reviews the project plan for technical hurdles and logic gaps |
| 12 | Capstone Execution | Phase 2: Component build-out and test integration | AI acts as a QA lead and suggests where testing should be expanded |
| 13 | Capstone Polish | Phase 3: A11y verification, SEO finalization, and deployment | Final automated audit of adherence to professional standards |

## Outcomes

By taking advantage of the opportunities this course presents, you will develop fundamental knowledge and skills in computing and technology and improve your professional possibilities by:

1. Translate user needs into technical blueprints using sitemaps, wireframes, and design system documentation.
2. Apply automated testing (unit and integration) to ensure application logic is bug-resistant.
3. Architect and implement advanced JavaScript patterns, including asynchronous flow and modular architecture.
4. Implement A11y patterns to ensure products meet professional WCAG standards.
5. Evaluate and refine AI-generated test suites and code reviews to ensure technical accuracy.

These outcomes extend WDD 235 outcomes from foundational mechanics into professional frontend engineering practice.

These outcomes support both the [CIT Department and BYU-Idaho student learning outcomes](universityandcitoutcomes.pdf). The activities and assessments for this course are designed to give you opportunities to achieve these outcomes and evaluate you against them. If you desire a different set of evaluations and assignments, you may propose them to the instructor (during the first or second week of the semester) but your proposal must cover ALL of the course's outcomes in significant ways and to a significant depth. Do not propose a "check list" of do-once-and-forget activities. These will not be approved.

## Learning Model Architecture

### Prepare

Each week you will work directly with your team. You help your team become successful if you come prepared for these team meetings. This preparation includes thinking about the technologies you are exploring, completing the assignments given during the previous team meeting, and doing the necessary research to plan the next steps for your team. Just as in life, if you do more than fulfill the minimum requirements assigned to you, you will be more successful in your team and in the class. Magnify your professional calling.

### Teach One Another

Team meetings and a collaborative environment have been established to enable each of you to draw from the strengths of others so that your weaknesses can become strengths. This requires effort on the part of both the knower and the learner so that 'both [may be] edified' (see Doctrine and Covenants 50:22).

### Ponder/Prove

Pondering is integral to success in both this course and life. You should be pondering and reflecting not only on what you are learning but how you are learning it. Self-understanding is vital to professional life. It is also fundamental to our eternal exaltation.

Proving is also integral to success. You should prove what you think you know through experimentation, implementation, and verification. In this course, that includes demonstrating test reliability, accessibility behavior, and architectural quality, not only visual completion.

## AI Usage Policy

Generative AI can be a valuable support tool in this course. AI use is allowed for educational purposes such as research, troubleshooting, architecture critique, and test ideation. You can usually assume that you can use AI to *help* you complete your assignments, but AI should *not* be used to *replace* your own engineering judgment.

In WDD 236, AI should function like a senior reviewer:

- Challenge your architecture assumptions.
- Suggest edge cases your tests may be missing.
- Flag potential accessibility or maintainability risks.
- Help you audit final quality before submission.

You are responsible for validating all AI output before submission.

Each assignment in this course will have a stoplight indicator on it that gives more specific direction on AI use for that assignment.
