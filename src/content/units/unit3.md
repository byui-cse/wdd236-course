## Ponder

- Classify likely failure points: boundary values, invalid input, async race conditions, and state transitions.
- Determine which tests should run at unit scope versus integration scope.

## Prove

- Build and run a test suite for at least one component and one pure logic module.
- Use AI to generate candidate boundary cases, then keep only tests you can justify and explain.
